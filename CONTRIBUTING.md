# Contributing

1. Use synthetic accounts and records only.
2. Write a regression test for the intended behavior, especially access boundaries.
3. Run the commands in the README. Keep dependency locks and migrations current.
4. Inspect `git diff --cached` and `git status --short` before committing. Never add `.local-data`, credentials, private code or real records.
5. Open a pull request explaining the user-visible change, relevant risks and actual verification results.

AI-assisted contributions are acceptable. Review generated code and documentation, verify claims and disclose material limitations. Do not claim manual authorship, independent review or passing tests that did not occur.
